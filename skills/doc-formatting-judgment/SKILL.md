# 書式判断（箇条書き・表・見出しの使い分け）

## 基本原則

- 説明は原則として文章（段落）で書く。
- 箇条書き・表・見出し・太字は、使うことで読み手の理解が明確に上がる場合にだけ使う。
- 書式は「読みやすさのための道具」であり、「整って見せるための装飾」ではない。
- 利用者が明示的に形式を指定した場合は、その指定に従う。

## 形式の選び方

| 内容の性質 | 使う形式 | 根拠 |
|---|---|---|
| 手順、時系列、順番に意味がある流れ | 番号付きリスト | Google開発者向けスタイルガイド、Microsoft Learn、digital.gov の各ガイドが、順序が重要な場合は番号付きとしている |
| 並列で独立した項目が3つ以上ある | 箇条書き | 文化庁「公用文作成の考え方」は三つ以上の情報を並べるときに箇条書きを利用するとしている |
| 同じ属性で複数の対象を比べる | 表 | digital.gov は複雑な関係や比較を明確にするために表を使うとしている |
| 理由、条件、因果、対比、考察 | 文章 | 箇条書きにすると論理のつながりが切れる（筆者の運用判断） |
| 項目が1〜2個しかない | 文章 | リストにする利点がない（筆者の運用判断） |
| 表のセルに長い説明が入る | 文章、または表を分ける | 表は長文の段落に向かない、とする指針が複数ある（下記出典参照） |

※ 表の列数や比較対象の数の目安（例: 3対象以上、5〜6列まで）は、出典に明記された数値ではなく、筆者の運用上の目安です。

## 箇条書きの注意点

- 各項目は同じ粒度・同じ文の形式にそろえる（Google、Microsoft Learn が並列構造を推奨）。
- 箇条書きの前には、何を並べるのかを示す導入文を置く（digital.gov、Google の「Lists and tables」が導入文の重要性に触れている）。
- 1項目は1〜2文以上の内容を持たせる。単語だけの項目が並ぶなら、文章にまとめる。
- 箇条書きの中に箇条書きを入れる入れ子は、2階層までにとどめる（筆者の運用判断）。
- 項目同士に因果や順序の関係があるなら、箇条書きではなく文章で結ぶ。
- 1つのまとまりの説明を、文ごとに項目へ分割しない。
- 箇条書きや番号の記号は、手入力の「・」「1.」ではなく、文書ツールのリスト機能を使う（Microsoft、Google、digital.gov のアクセシビリティ指針）。
- 使いすぎに注意する。重要な情報を強調するための道具であり、些末な事項まで箇条書きにしない（digital.gov）。

## 表の注意点

- 表は「比較する対象」と「比較する属性」が明確にあるときに使う。
- 表には分かりやすい標題を付け、表の前に導入文を置く（文化庁、Google の「Lists and tables」）。
- 表のヘッダーは明確にし、列の内容は簡潔にする（Google、Microsoft の表の指針）。
- 表の中に段落や長文を入れない（表は段落の代わりに使うものではない、とする指針が複数ある）。
- 表は「データの表示」に使い、「文章の段組み」や「レイアウト調整」には使わない（Microsoft、アクセシビリティ関連の指針）。
- 表の前後には、その表から何が読み取れるかを一文で添える（筆者の運用判断）。
- 1つの表に無関係な情報を詰め込まない。

## 見出し・太字の注意点

- 見出しは、文書が複数の独立したまとまりを持つときに使う（文化庁は「分量の多い文書」で見出しを使うとしている）。短い回答に見出しは不要。
- 見出しを追えば文書の流れがつかめるようにする（文化庁）。
- 太字は、読み手が最も見落としてはいけない語句だけに限る。段落内に多用しない（筆者の運用判断）。
- 見出し、太字、箇条書きを同時に多用すると、どこが重要か分からなくなるので避ける（筆者の運用判断）。

## 避けるべき過剰な書式化

- 短い回答を見出しと箇条書きで組み立てる。
- 理由や考察を箇条書きに分解して、論理のつながりを失わせる。
- 比較するほどの対象がないのに表にする。
- 一文で済む内容に箇条書きを使う。
- 本来は文章で書けるものを、書式で「整理された感」を出すために使う。

## 適用手順

1. 書く内容が、手順、並列項目、比較、論理的説明のどれに当たるかを判断する。
2. 上の表に従って形式を選ぶ。迷ったら文章で書く。
3. 箇条書きや表を使った場合は、上の注意点を満たしているか確認する。
4. 書式がなくても伝わるなら、書式を外す。

## 例外

- 利用者が「表にして」「箇条書きで」などと明示した場合は、その指定を優先する。
- 文書の種類に定められた書式（社内規定の様式、公文書の形式など）がある場合は、その様式に従う。
- コードブロック、数式、ファイルの書式が必要な場合は、その形式を使う。

## 出典

以下は原本を確認したものです。

- Google Developers Documentation Style Guide「Highlights」: 順序には番号付きリスト、それ以外の多くのリストには箇条書きを使う。 https://developers.google.com/style/highlights?hl=ko
- Google Developers「Lists and tables」（Tech Writing）: 表にはヘッダーと導入文を付ける。順序が意味を持つ場合は番号付きリストを使う。 https://developers.google.com/tech-writing/one/lists-and-tables?authuser=6
- Microsoft Learn「Lists」（Writing Style Guide）: 並列項目には箇条書き、手順や優先順位のある項目には番号付きリストを使う。 https://learn.microsoft.com/en-us/style-guide/scannable-content/lists
- digital.gov「Plain language guide series: Lists」（plainlanguage.gov の内容を移管したもの）: 順序の説明には番号付きリスト、導入文を添える、リストの使いすぎに注意する。 https://digital.gov/guides/plain-language/design/lists
- 文化庁「公用文作成の考え方」（令和4年1月7日 文化審議会建議）: 三つ以上の情報を並べるときは箇条書きを利用する。図表は分かりやすい位置に標題を付ける。 https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93731901_01.pdf
- Nielsen Norman Group「Why Web Users Scan Instead of Reading」（Jakob Nielsen, 1997年、2010年更新）: 利用者の79%がWebページを読まずにスキャンすると報告している。箇条書きや表の使い分けそのものは扱っていない。 https://www.nngroup.com/articles/why-web-users-scan-instead-reading/
